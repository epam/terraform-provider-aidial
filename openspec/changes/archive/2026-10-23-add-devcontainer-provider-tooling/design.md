# Design

## Context

`.devcontainer/` already builds from `golang:${GO_VERSION}` (1.27.3) with pinned ARGs for Terraform, gitleaks and glab, runs as user `node` (uid 1000) with `/home/node` on a persistent volume, and `post-create.sh` already runs `go mod download` and `pre-commit install`. `go.mod` says `go 1.21` (a floor, not a toolchain target). `main.go` serves the provider via `providerserver.Serve` without a `-debug` flag. `.vscode/` is gitignored. There is no Makefile or lint config. See proposal.md for motivation.

## Goals / Non-Goals

**Goals:**
- Everything in `specs/devcontainer-tooling/spec.md` works in a freshly built container.
- Tool versions are reproducible and bumped in one place (Dockerfile ARGs).

**Non-Goals:**
- Changing provider behavior, `main.go`, or the active CI.
- Reattach-style provider debugging (needs `-debug` support in `main.go`).

## Decisions

- **Go version**: keep the existing `GO_VERSION` ARG; it satisfies `go.mod`'s floor. Aligning literally to `go.mod` would downgrade the toolchain, so not done. CI uses `golang:1.24`; no change.
- **Tool installation**: `go install <tool>@<pinned>` in the Dockerfile as root with `GOBIN=/usr/local/go-tools`, added to `PATH`, so tools survive the `/home/node` volume mount (a `GOPATH` under home would be shadowed by the volume). `GOPATH=/home/node/go` stays in the volume for the module cache. `golangci-lint` is installed from its release tarball (as upstream recommends over `go install`), like gitleaks/glab in the Dockerfile. Alternative `@latest` rejected for reproducibility. Exception: `tfproviderlint` v0.31.0 fails on Go 1.27 ("package bytes without types") because its own `golang.org/x/tools` is too old, so it is built in a temporary module with `golang.org/x/tools` bumped to the `GOTOOLS_VERSION` pin.
- **dev_overrides**: `post-create.sh` writes `~/.terraformrc` only if absent, with an absolute path derived from the workspace folder (`dist/linux_amd64`, already gitignored). Because the home volume persists, existing files are never clobbered; README documents how to edit it. Terraform is run without `terraform init` while the override is active (as in AGENTS.md).
- **Debugging**: `.vscode/launch.json` with "Debug test (current file)" and "Debug test (package)" using `mode: test`. `.gitignore` changes `.vscode/` to `.vscode/*` plus `!.vscode/launch.json`. Provider-binary debugging is left out because it needs a `-debug` flag in `main.go`.
- **Make targets**: thin wrappers over AGENTS.md commands; `lint` runs `golangci-lint run` then `tfproviderlint ./...`; `lint-md` runs `markdownlint-cli2`; `docs` runs `tfplugindocs generate --provider-name dial`, which needs `terraform` on `PATH` and writes to `docs/` (not committed here).
- **golangci-lint config**: minimal `.golangci.yml` (govet, errcheck, staticcheck, ineffassign, unused, gofmt, goimports). If existing code has findings, fix trivial ones; otherwise narrow the config so `golangci-lint run` exits 0 (acceptance criterion). Outcome: goimports fixes in two files, and errcheck excludes `io.Closer.Close`, `ResponseWriter.Write` and `providerserver.Serve` (deferred closes, test handlers and the provider entry point) rather than editing Go code.
- **Markdown lint**: `markdownlint-cli2` installed with npm in the existing Node layer (pinned ARG); the VS Code markdownlint extension is already configured. `.markdownlint-cli2.jsonc` disables MD013 (line length) and MD060, and ignores `openspec/**` (generated by the OpenSpec CLI, hundreds of findings) and `.claude/**` (user-local files). Existing README/AGENTS findings were fixed with `--fix` (blank lines around fences/lists/headings, one fence language).
- **OpenSpec skills**: the skills and `/opsx:*` commands are copied to `~/.claude/` (a host bind mount, so they persist across rebuilds) and removed from the repo with `git rm`. Trade-off: other contributors must install them themselves; `AGENTS.md` records the location.
- **Pre-commit**: add local hooks for goimports, golangci-lint (`pass_filenames: false`), tfproviderlint and markdownlint, matching the existing `language: system/golang` style.

## Risks / Trade-offs

- [`tfproviderlint` targets the SDKv2 and may find little in a Plugin Framework provider] → included as requested; keep non-blocking in pre-commit if noisy.
- [Pinned versions may not exist/resolve for Go 1.27.3 at implementation time] → verify each version builds during the Dockerfile task; bump the ARG as needed.
- [Image rebuild needs network and takes longer] → tool installs are in a cached layer before the frequently changing steps.
- [Existing `~/.terraformrc` in the volume lacks the override] → documented in README; post-create prints a notice instead of editing.
