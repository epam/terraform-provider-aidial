# Contributing

Thanks for helping improve the provider. The [README](README.md) covers the devcontainer, `make` targets and local builds.

## Workflow

1. Open an issue for larger changes before starting.
2. Behavior is specified under `openspec/`. Update the spec and the code together.
3. Add or update unit tests next to the code (`internal/provider`, `internal/client`).
4. Run the checks CI runs:

   ```bash
   go test ./... -count=1 -race
   test -z "$(gofmt -l .)"
   go vet ./...
   make lint lint-md
   terraform fmt -check -recursive
   make docs && git diff --exit-code docs/
   ```

5. Use [Semantic Commit Messages](https://www.conventionalcommits.org/) (`type: subject`, for example `feat:`, `fix:`, `docs:`, `chore:`) for commits and pull request titles. Keep the subject imperative and lowercase after the type.

`docs/` is generated by `tfplugindocs` from the provider schema and `examples/`; do not edit it by hand.

## Releasing (maintainers)

See [Releasing](README.md#releasing) in the README. In short: update `CHANGELOG.md`, tag `vX.Y.Z` and push the tag; the release workflow does the rest.
